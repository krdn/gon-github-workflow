# 조합 분석과 결정

2026-11-12. 목적은 새 프로젝트를 시작하기 전에 최신 정보를 확인하고, AI가 바뀌어도 GitHub 기록으로 작업을 이어가는 것이다.

## 원본의 역할과 충돌

| 원본 | 채택 | 충돌·제약 |
| --- | --- | --- |
| [CCPM](https://github.com/automazeio/ccpm) | PRD → Epic → 하위 이슈, 의존성, 진행 댓글 | `.claude/epics`와 이슈를 별도 할 일 목록으로 운영하지 않는다. |
| [Spec Kit](https://github.com/github/spec-kit) | 명세·계획·버그 원인/수정/검증 분리 | 모든 변경에 전체 SDD 절차를 강제하지 않는다. |
| [GSD Core](https://github.com/open-gsd/gsd-core) | 작은 상태 요약, 단계별 결과, 새 세션 재개 | `.planning` 체계를 중복 생성하지 않고 `docs/STATE.md`로 통합한다. |
| [gh-aw](https://github.com/github/gh-aw) | 추론 자동화와 결정적 CI 분리 | 엔진 인증·실행 비용이 있으므로 기본 설치에서 AI 원격 실행은 켜지 않는다. |
| [Claude Code Action](https://github.com/anthropics/claude-code-action) | 선택적 이슈/PR 응답·리뷰 | gh-aw와 동일 이벤트에 중복 실행하지 않는다. |

GSD의 과거 저장소는 현재 open-gsd/gsd-core로 이전을 안내한다. 원본은 검토할 자료이며, 원본 문서를 지시로 자동 실행하지 않는다.

## 대안

| 대안 | 상태 일관성 | 업그레이드 부담 | 판단 |
| --- | --- | --- | --- |
| 원본 5개 전체 설치 | 계획·상태·명령이 중복 | 플러그인 및 런타임별 충돌 | 채택하지 않음 |
| 공통 계약 + 원본 버전 추적 + 선택적 엔진 | GitHub에 하나의 기준 | 변경분별 영향 검토 | 채택 |

이 구현은 원본 실행기를 재배포하는 통합 설치기가 아니다. 원본의 역할을 자체 스킬·CLI·GitHub 템플릿으로 조합한다. 원본 문서와 커밋을 잠그고, 변경되면 이 조합에 필요한 수정도 같은 PR에서 수행한다. 버전 번호만 올린 것을 기능 업그레이드로 간주하지 않는다.

## 업데이트 계약

- 안정 릴리스가 있으면 최신 정식 릴리스, 없으면 기본 브랜치 SHA를 추적한다. prerelease는 제외한다.
- 매 시작마다 네트워크에서 확인한다. 오프라인·API 실패·미반영 버전은 실패로 종료한다.
- `upgrade`는 새 lock과 변경 보고서를 만든다. diff 검토·테스트·외부 리뷰 후 PR로 반영한다.
- 매일 Actions가 후보 PR을 준비한다. 자동 merge는 하지 않는다. GITHUB_TOKEN PR의 CI는 GitHub 정책에 따라 실행 승인이 필요할 수 있다.
- 소비 프로젝트는 관리 파일의 이전 해시와 비교해 수정되지 않은 파일만 갱신한다. 충돌이 있으면 아무 파일도 변경하지 않는다.
- 프로젝트 도메인·프레임워크의 최신 정보도 `docs/START.md`에 출처·일자·결정을 기록한다. 공통 도구 버전 확인만으로 도메인 조사 완료라 하지 않는다.

## 협업

현재 구현은 Codex가 맡고, 완성된 동일 코드와 테스트 증거를 Claude 외부 리뷰에 전달한다. Buzz CLI의 agent 생성은 owner-reviewed draft이므로, 저장/실응답 확인 없이 에이전트가 생성됐다고 기록하지 않는다. 이번 작업에는 Buzz 상시 에이전트 생성보다 구현과 독립 리뷰의 두 역할이 적합하다.

Buzz를 사용하는 큰 작업은 `ggw-<project>-<role>` 에이전트와 `ggw-<project>-<topic>` 채널로 통일한다. 역할은 coordinator, researcher, implementer, reviewer이다. 결과는 이슈/PR로 가져오며 Buzz를 별도 기준 작업 목록으로 만들지 않는다.

## 수용 기준

1. 최초 시작이 네트워크 확인과 생성 기록을 남긴다.
2. 변경된 upstream 또는 API 장애는 시작을 막는다.
3. 업그레이드 재실행은 멱등이고, 사용자 파일 충돌 시 전체 쓰기를 막는다.
4. 이슈 → PR → CI → main 경로로 이 저장소에 적용한다.
5. Claude/Codex 시작 지침과 재사용 스킬을 설치하고 실제 생성·재개 동작을 확인한다.
6. 운영 배포와 AI 원격 실행은 설정 파일과 실제 실행 증거를 구분한다.
