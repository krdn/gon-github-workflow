# 프로젝트 구성 코드 리뷰

2026-11-13. 실행기 `~/.codex/bin/review-llm`, 요청·실제 반환 모델 `claude-opus-5-5`, effort high.
최초 리뷰와 수정분 재검토를 각각 한 번 수행했다. 두 응답 모두 지적이 있어 FAIL이었다.
아래 여섯 결함을 회귀 테스트로 재현하고 수정했다. 마지막 대소문자 수정은 직접 테스트했으며 세 번째 외부 호출은 하지 않았다.

| 지적 | 처리·검증 |
| --- | --- |
| 신규 원격에 잘못된 로컬 브랜치 푸시 | 원격 기본 브랜치와 다르면 커밋·푸시 전 중단 |
| 미추적 개인 인수인계·조사 파일 커밋 | 실제 생성 기록이 있는 seed만 추가, 기존 메모 보존 |
| 기존 Dependabot 파일 충돌 | 없을 때만 생성하고 사용자 설정 보존 |
| merge 후 로컬 브랜치 삭제 시 재개 실패 | 원격 PR의 MERGED 상태부터 확인 |
| commit hook 실패 후 stage/브랜치 잔류 | 해당 stage만 해제, 원래 브랜치 복귀, 생성 해시가 일치할 때 재개 |
| 이슈 URL의 정식 대소문자 차이 | 저장소 경로를 대소문자 무시 비교 |

부가 수정: gh의 Git 프로토콜 존중, HTTPS 프롬프트 차단, 기존 Issues 설정 사전 확인,
라벨 대소문자 비교, 이슈 저장소·Milestone 번호·Project 목록 잘림 확인.
전역 설치기·스킬·프로젝트 지침을 같은 릴리스에서 갱신해 ready 의미 변경을 전달한다.

검증: 전체 36개 unittest 통과. Git은 실제 임시 bare remote를 사용하고 GitHub 경계만 mock한다.
start 전체 연속 실행, 실패 복구, 브랜치·개인 파일 보존과 대소문자 회귀를 포함한다.
실제 HTTPS GitHub 구성과 CI 근거는 [검증 기록](setup-verification.md)에 있다.

제한: 실제 SSH 인증 경로는 미검증. 닫힌 구성 PR은 다시 열어 재개한다.
파일을 수정하는 hook이 실패하면 생성 해시가 달라져 자동 재개를 차단한다.
구성 CI는 PR에서 push·pull_request 두 번 실행될 수 있다.
