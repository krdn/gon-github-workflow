# GitHub 기준 설계·구현·세션 계획

기준 [#27](https://github.com/krdn/gon-github-workflow/issues/27), [조사 근거](../research/github-session-2026-11.md).

## 운영 계약

설계·구현의 목표/범위/완료 조건을 이슈에 먼저 기록한다. 설계·작업 파일을 커밋·푸시하고 원격 링크를 이슈에 남긴다. 새 세션은 해당 기록을 먼저 확인한다. 진행 중 범위 변경·실패·추가 기능도 같은 이슈 또는 후속 이슈에 반영한다. 단순 질의에는 이슈를 만들지 않으며 작은 변경은 기존 이슈를 재사용한다.

추가 기능은 현재 목표에 필요한 범위만 포함하고 이유·검증 조건을 기록한다. 독립 기능은 후속 이슈로 분리한다. 계획 등록은 거래·배포·삭제 등의 실행 승인을 뜻하지 않는다.

## 명령 계약

`gon-workflow resume PATH --issue URL --task PATH [--plan PATH ...] [--pr URL ...]`

1. handoff와 공통으로 Git 루트/origin/미커밋/브랜치와 GitHub SHA, STATE·작업 파일의 커밋/원격 blob을 확인한다.
2. 선택 작업 파일의 정확한 이슈 URL과 열린 이슈를 확인한다. 닫힌 작업은 상태를 검토한 뒤 후속 이슈 또는 승인된 재개 기록으로 처리한다. 자동 재개방하지 않는다.
3. 명시한 설계 파일을 같은 검증에 포함한다. 별도 설계가 없으면 작업 파일 자체가 계획 역할을 한다.
4. native blocked_by 전 페이지의 URL·제목·state·state_reason을 출력한다. 완료 사유와 통합·수용은 사람이 추가 확인한다.
5. 명시한 같은 저장소 PR의 상태·head SHA·draft·리뷰·CI를 조회한다. CI 실패 수정 세션도 가능하므로 CI 성공을 명령 실행의 전제로 삼지 않는다.
6. JSON으로 관측 시각·고정 문서 링크·관계·PR/CI·새 세션 미실행을 출력한다. 오류가 있으면 성공 보고 없이 종료한다. 출력 자체를 승인/수용/배포 성공으로 쓰지 않는다.

작업 파일·설계 목록의 의미적 완전성, 사람이 쓴 승인, 지정하지 않은 PR은 자동 검증하지 않는다. 원격 조회는 순간 관측이며 세션 잠금이 아니다. 다른 worktree의 파일과 미커밋 변경은 보존한다. 시작 전 변경이 있으면 자동 stash/commit/delete하지 않고 소유권과 보존 위치를 확인한다.

## 변경과 검증

- workflow.py: 기존 handoff 준비부 재사용 + resume CLI. 기존 전달문·댓글 중복 방지는 보존한다.
- install.py·스킬·AGENTS/WORKFLOW/task 템플릿: 선기록, resume, 추가 기능 범위, 실패 복구·원격 전달 규칙.
- 단위: 잘못된/닫힌 이슈, 미주입 작업 URL, dirty/unpushed/blob 불일치, 설계 누락/경로 탈출, 의존성 페이지·실패, PR 실패/빈 CI/다른 저장소를 검증한다.
- 실제 검사: 커밋·푸시된 #27 기록으로 읽기 전용 resume을 실행한다. 전체 unittest·validate --reviewed·diff 검사와 독립 리뷰·PR CI를 확인한다.
- 배포: 리뷰·CI 통과 후 main 통합, 중앙 checkout과 전역 설치 블록을 갱신한다. 기존 소비 프로젝트는 파일별 수동 통합 또는 이후 명시적 갱신으로 적용한다.
