# ADR-0001: 그래프 DB 도입을 보류한다

상태: 확정. 날짜: 2026-11-15. 기준: [이슈 #23](https://github.com/krdn/gon-github-workflow/issues/23).
근거: [연구](../../research/github-claude-mem-graph-2026-11.md), [검토·검증 기록](../../tasks/23-graph-memory-review.md).

GitHub·작업 파일·claude-mem의 기존 절차를 유지한다. Neo4j·Graphiti 설치, 새 수집기, CLI·템플릿·메모리 설정 변경은 수행하지 않는다.

## 판단 근거

실제 24개 이슈의 52개 관계는 GitHub API와 짧은 순회로 조회했다. 새 DB의 성능·정확성·업무 개선 효과는 측정하지 않았다.
결정 변경·검증 근거까지 연결하는 활용법은 유망한 가설이지만, 그 관계 데이터와 기존 절차의 실제 실패 사례는 수집하지 않았다.
관찰의 전체 URL 부족은 식별자 품질의 문제다. 기존 작업 템플릿에는 이미 이슈/PR·SHA·선행 관계·검증·수용 항목이 있다.
새 DB를 추가하면 수집·동기화·권한·삭제·오연결 관리가 필요하다. 현재 증거로 그 비용을 정당화할 수 없다.

| 대안 | 판단 |
|---|---|
| 기존 GitHub·작업 기록·claude-mem 유지 | 채택. 확인된 작업을 수행할 수 있고 새 운영 요소가 없다. |
| API 직접 조회와 짧은 스크립트·별도 SQLite | 현재 구현하지 않는다. 실제 반복 문제가 기록되면 먼저 비교할 후보로 둔다. |
| Neo4j 또는 Graphiti 추가 | 보류. 더 단순한 방식의 한계와 추가 효과가 입증되지 않았다. |

## 결과와 재검토 조건

연구·근거·이 결정을 저장소에 남긴다. 자동 PoC와 운영 업그레이드를 시작하지 않는다.
기존 재개 절차와 native API를 따랐는데도 누락·오판 또는 과도한 수집 비용이 실제 작업 기록으로 남으면 검토를 재개한다.
그 문제에 필요한 관계를 수집할 수 있는지 먼저 확인하고, 같은 질문에서 API·스크립트·SQLite와 비교한다.
더 단순한 방식이 동등하면 DB를 추가하지 않는다. 도입 기준과 비용 한도는 기준선 측정 뒤, 비교 전에 정한다.

이 결정으로 복합 관계 탐색의 잠재적 편익은 당장 얻지 못한다. 대신 아직 필요성이 확인되지 않은 운영 부담을 피한다.
데이터량 증가나 새 도구 출시만으로 결정을 뒤집지 않는다. 검증된 문제와 비교 결과를 근거로 변경한다.
