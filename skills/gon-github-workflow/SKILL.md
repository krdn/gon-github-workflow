# 새 대화에서 GitHub 작업 이어가기

1. 저장소의 `AGENTS.md`와 `docs/STATE.md`에서 사용자가 지정한 이슈와 작업 문서를 찾는다. 이슈 번호만 받으면 현재 저장소의 URL로 풀고, 지정이 없으면 STATE의 현재 작업을 따른다. 해당 작업 문서와 필수 자료부터 읽는다.
2. 저장소 루트에서 다음 명령으로 원격 기록을 확인한다. 실제 이슈 URL과 작업 파일 경로를 넣고, 별도 설계마다 `--plan <파일>`, 관련 PR마다 `--pr <URL>`을 붙인다.

   ```sh
   gon-workflow resume . --issue "$issue_url" --task "$task_file"
   ```

3. 결과의 이슈 상태와 선행 이슈 종료 사유, 관련 PR의 병합 상태·대상 커밋·CI를 작업 문서와 대조한다. 누락된 PR이나 비어 있는 CI는 직접 조회한다. 완료 조건과 대조해 이미 끝난 일은 건너뛰고 승인된 범위의 다음 작업부터 진행한다.

미커밋 변경이나 원격 SHA 차이로 검사가 멈추면 기존 작업을 보존하고 브랜치·커밋과 이슈·PR을 읽기 전용으로 대조한다. 확인한 사실과 남은 차이를 밝힌다. `resume`은 기록을 조회한다. 새 세션 생성, 사용자 수용, 거래·배포 승인은 각각 별도 근거로 확인한다.
